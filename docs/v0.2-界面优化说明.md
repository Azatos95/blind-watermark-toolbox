# 盲水印工具箱 v0.2 — 界面与交互优化说明

> 在 v0.1(打包验证原型)基础上, 按"三个面板互不影响 / 响应式 / 傻瓜式 / 拖拽 / 默认输出路径"要求重构。
> 产物: `dist\盲水印工具箱.exe` (单文件 61.1 MB)

---

## 一、本次改了什么

### 1. 嵌入按钮彻底解耦 —— 三个面板互不影响

v0.1 是"一个页面 + 单选按钮切换水印类型", 两类嵌入共用一套控件和校验, 会互相污染。
v0.2 改成 **三个独立标签页, 各自持有自己的控件、变量和按钮**:

| 标签页 | 按钮文案 | 输入控件 |
|---|---|---|
| ① 嵌入文字水印 | 开始嵌入文字水印 | 原图 + 文字框 + 两枚密码 + 输出路径 |
| ② 嵌入图片水印 | 开始嵌入图片水印 | 原图 + 水印图 + 两枚密码 + 输出路径 |
| ③ 提取水印 | 开始提取文字水印 / 开始提取图片水印 | 成品图 + 模式 + 长度或尺寸 + 两枚密码 + 结果目录 |

代码层面就是三个类 `TextTab` / `ImageTab` / `ExtractTab`, 各自 `self.src / self.out / self.pwd_img …` 完全独立,
不存在任何共享状态。实测验证:

```
①文字页按钮: 开始嵌入文字水印 | ②图片页按钮: 开始嵌入图片水印
两页状态互不干扰: 文字页src=A 图片页src=B
拖拽接收方随标签页切换: 文字页->TextTab  图片页->ImageTab  提取页->ExtractTab
提取页 文字模式: 按钮=开始提取文字水印  长度行=显示 尺寸行=隐藏
提取页 图片模式: 按钮=开始提取图片水印  长度行=隐藏 尺寸行=显示
```

### 2. 响应式布局

- 全部改用 `grid` + `columnconfigure(weight=1)`, 输入框随窗口拉宽, 按钮贴右, 不出现挤压。
- 窗口最小 720×600, 默认 900×720 居中; 各标签页内容高度都小于可视高度, **任意尺寸下主要控件都不会被裁掉**。
- 自动化校验脚本 `layout_check.py` 在 5 种窗口尺寸 × 3 个标签页下逐页测量内容高与可视高:

```
900x720 / 720x600 / 1100x820 / 1280x900 / 760x620  → ALL_FIT=True
```

> 踩过的坑: 一开始我加了一个"弹性空白行"想让多余空间沉底, 结果窗口最大化时中间出现一大块空白
> (截图对比后确认), 已改为内容顶部对齐 + 不做纵向拉伸。

### 3. 界面简化与"傻瓜式"设计

- 顶部一行字说清"能做什么" + 右侧 `拖拽已就绪` 状态徽标。
- 每页只有 **一块拖拽区 + 一个主按钮**(蓝色大按钮), 其余是可不管的默认值。
- 拖拽区本身就带引导语("把【原图】拖到这里, 或点击选择"), 载入后变成 `✅ 已载入 — 拖入新图片可更换`。
- 密码默认填 `123` 并标"嵌入与提取必须一致"; 高级项(输出路径)给默认值, 不打扰用户。
- 文字页实时显示 **占用 N bit / 该图最多可放约 M bit**, 超容量提前预警, 而不是等报错。
- 底部状态条 + 进度条 + 可折叠日志(默认收起按钮在右下), 出错给中文人话提示, 不甩 traceback。

### 4. 图片拖入添加

用 `tkinterdnd2`(内置 TkDND 2.10.2 扩展)。要点:

- 拖拽接收方 **跟随当前标签页**, 在图片页两次拖入按顺序成为"原图 → 水印图"。
- 拖入即自动填输出路径、自动刷新容量提示。
- 打包时用 `collect_data_files('tkinterdnd2')` 把 tkdnd 原生扩展原样带进 exe
  (Tcl 需要从磁盘加载它, **不能压进单文件**), 否则打包后会静默失去拖拽能力。
- 做了容错: 万一某台机器 tkdnd 加载不了, 程序照常启动, 只把徽标显示成"拖拽不可用", 浏览按钮仍可用。

打包产物自检里专门加了拖拽链路验证:

```
tkdnd drop_target ok (registered)
tk_root=OK tkdnd_version=2.10.2
app_dnd targets=1 bind=..._on_drop ...
```

### 5. 默认成品输出路径

- 默认输出到 **桌面\盲水印输出**, 文件名自动推导: `原图名_文字水印.png` / `原图名_图片水印.png` /
  `原图名_提取出的水印.png` / `原图名_水印内容.txt`。
- **可写性探测 + 逐级回退**: 桌面写不了(只读桌面/安全软件锁)就依次退到
  `Documents\盲水印输出` → `用户目录\盲水印输出` → `~/.dsh\盲水印输出` → 当前目录, 绝不让用户存不下结果。
- 输出路径旁有 `浏览 / 打开` 按钮; 底部常驻 `打开输出目录`; 嵌完/提完自动弹出所在文件夹。

### 6. 附加: 顺手解决的"第二天提不出来"

嵌入时自动在同目录生成同名 `xxx.bwm.json`(记录版本、密码、水印 bit 长度或图片尺寸、原文),
提取时拖入成品图即 **自动回填全部参数**, 直接点提取即可, 界面也会亮出
`✔ 已读取同名信息文件, 参数自动填好`。

## 二、顺手修掉的两个真 bug

优化过程中通过"模拟用户点击"的端到端测试暴露出来的, 都不是界面问题:

| # | Bug | 后果 | 修法 |
|---|---|---|---|
| 1 | `open_folder()` 直接调 `os.startfile()`, 而它是**后台工作线程**调用的 | 非主线程没有 STA 消息泵, 该调用可能卡死或抛 `WinError 5 拒绝访问`, 把整个嵌入流程拖住 | 改用 `explorer /select,`;`os.startfile` 只作兜底且放进守护线程 + 2 秒超时, 保证"永不阻塞、永不抛异常" |
| 2 | 工作线程用 `self.after(0, …)` 回传结果给主线程 | Tk 处于非 `mainloop` 事件泵时抛 `RuntimeError: main thread is not in main loop`, 任务结果永远回不来, 界面一直卡在"处理中" | 改为**完成队列** `doneq`, 由主线程的定时器统一收尾, 工作线程完全不碰 Tk |

## 四、新增/变更文件

| 文件 | 说明 |
|---|---|
| `bwm_gui.py` | v0.2 主程序(三个独立面板 / 响应式 / 拖拽 / 默认输出 / 侧车文件) |
| `bwm_gui.spec` | 打包配置(新增 tkinterdnd2 数据文件收集) |
| `gui_flow_test.py` | 模拟用户点击的端到端测试(真实 mainloop) |
| `layout_check.py` | 响应式布局自动校验(多尺寸 × 多标签页) |
| `independence_check.py` | 面板独立性与模式切换校验 |
| `shot/pw_*.png` | 三个标签页的最终界面截图 |
| `dist/盲水印工具箱.exe` | 成品单文件 exe |

**重建命令**:

```powershell
python -m venv --system-site-packages .venv-build
.venv-build\Scripts\python.exe -m pip install tkinterdnd2      # 拖拽支持
.venv-build\Scripts\python.exe -m PyInstaller --noconfirm --clean bwm_gui.spec
.venv-build\Scripts\python.exe dist\盲水印工具箱.exe --selftest # 自检
```

**运行提示**: 请把 exe 拷到**工作区之外的普通目录**再运行。在 DSH 沙箱的工作区内直接跑单文件 exe 时,
PyInstaller 解压到 `%TEMP%` 会报 `Could not create temporary directory!` —— 这是沙箱限制, 与程序无关。

## 五、还可以继续做的(按性价比排序)

1. **记住上次的密码与目录**(配置文件), 少填两次。
2. **批量模式**: 拖入多张图 / 整个文件夹, 进度条 + 取消(线程模型已具备, 扩起来不难)。
3. **预览对比**: 嵌入前后并排小图 + 肉眼对比开关。
4. **集成 `recover.py`**: 被截图/旋转的图先自动纠偏再提取, 进一步降低使用门槛。
5. **代码签名**: 否则首次运行仍会被 SmartScreen 拦一下。
6. **图标**: `bwm_gui.spec` 里 `icon=None` 预留, 换成 `app.ico` 即可。
