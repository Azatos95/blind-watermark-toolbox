# 盲水印工具箱 v0.3 — 界面与功能优化说明

> 本轮目标：**历史密码记忆 + 深色直角界面 + 警戒线式运行状态栏 + 思源黑体**。
> 产物：`dist\盲水印工具箱.exe`（单文件 **61.1 MB**，版本 `0.3.0.0`，自检 `SELF_TEST=PASS`）

## 一、历史密码记忆（本轮核心新功能）

**问题**：blind_watermark 提取时必须提供两枚密码 + 水印长度，用户在"第二天"很容易忘掉密码，导致水印永远解不开。

**做法**：新增 `bwm_theme.History`，把每次成功使用的密码记录下来，并在提取时自动填入。

| 位置 | 行为 |
|---|---|
| 记录时机 | 嵌入成功、提取成功后各记一次（按使用次数排序） |
| 提取页 | 打开软件时**自动填入上次的两枚密码** |
| 提取页"历史"行 | 最近 4 组密码对做成**可点小标签**（如 `5566 / 7788`），点一下同时填入 A/B |
| 密码框旁 `▾` | 下拉列出历史密码（去重、按次数排序），单选填入 |
| 嵌入页 | 密码默认值直接沿用上次使用的那组，不用每次重打 |
| 输出目录 | 同时记住最近用过的输出目录，提取页默认使用 |
| 存放位置 | `%APPDATA%\盲水印工具箱\history.json`（约 1 KB） |
| 隐私边界 | **只存密码、使用次数、最近输出目录**；不保存图片内容、不保存水印明文 |

**实测**（`scripts/gui_flow_test.py`）：

```
① 文字水印: 用密码 5566/7788 嵌入 -> ori_img_文字水印.png
   历史文件已写入 = True
   记住的密码对 = [['5566', '7788']]
   记住的图片密码 = ['5566']
③ 重开软件(模拟第二天)+ 提取
   提取页自动填入: A=5566 B=7788          ← 自动填入生效
   提取页历史标签 = ['5566 / 7788']        ← 历史标签渲染
   拖入成品后: 长度=175 密码=(5566,7788)   ← 侧车文件回填长度
   取回文字 = 'v0.3历史密码测试'            ← 与原文完全一致
FLOW_TEST=PASS
```

## 二、深色直角界面（含配色规范）

| 用途 | 色值 | 用在哪 |
|---|---|---|
| 主背景 | `#121416` | 窗口底色、标签页未选中页、状态条 |
| 次级面板 | `#1A1D20` | 卡片、内嵌面板、参数区 |
| 细框线 | `#303438` | 卡片外框、输入框描边、按钮描边、分割线 |
| 强调色 | `#D6B046` | 主按钮、选中标签、输入框焦点框、历史标签竖条、顶部细线 |

其他派生色（为深色可读性服务）：面板上的输入控件 `#20242A`、卡片内弱分割线 `#24282B`、
正文 `#E6E8EA`、次要文字 `#9AA0A6`、弱文字 `#6B7076`。

**"全部直角"的落实**：

- 卡片 = 外层 1px 细框线 Frame + 内层面板色 Frame 叠 1px 内边距 → 视觉是干净的直角描边。
- 按钮：`relief='flat'` + `bd=0`；次要按钮用 `highlightthickness=1` 画 1px 直角描边。
- 输入框：`relief='flat'`，常态 1px 细框线，聚焦变强调色（去掉系统立体边框）。
- 标签页：重写 `TNotebook` 布局（`st.layout` 只保留 `Notebook.client`），去掉 clam 主题的圆角与立体感。
- **水印类型选择**：原来是深色下发暗的 `tk.Radiobutton` 圆圈，改为自定义直角切换按钮 `Toggle`
  —— 选中态用 `#D6B046` 描边 + 强调色文字 + `#2A2517` 淡底，一眼可辨。
- 日志滚动条：重写 `Vertical.TScrollbar` 布局去掉上下箭头方块，滑块改为 6px 细条，hover 变强调色。

**实测**（自检 + 流程测试）：

## 三、警戒线式运行装饰状态栏

窗口顶部是一条 5px 高的**45° 斜纹警戒线**（`Canvas` 逐条画 2px 斜线），下方压一条 1px 强调色细线，
形成"警戒带"的装饰感。颜色即状态：

| 状态 | 颜色 | 触发时机 |
|---|---|---|
| 运行正常 | **灰绿 `#7E9B84`** | 启动、任务成功完成 |
| 出错 | **红 `#C0453F`** | 提取失败（密码/长度不对）、读图失败、水印超容量、写文件失败等 |
| 处理中 | 强调色 `#D6B046` | 正在嵌入 / 提取 |

底部状态条同步显示 `● 正常 / ● 处理中 / ● 异常`，颜色与警戒线一致，
右侧仍是"打开输出目录 / 收起日志"两个直角按钮 + 细进度条。

**实测**：

```
正常=灰绿 True | 出错=红 True | 处理中=强调 True -> OK
```

> 实现细节：`set_state('ok'|'err'|'busy')` 统一入口，Canvas 重绘时按当前状态取色；
> 底部圆点与顶部斜纹共用一个颜色源，不会出现两处不一致。

## 四、字体：思源黑体 Bold / Medium

- 启动时**探测本机可用字体**，按 `Source Han Sans SC Bold → Noto Sans SC Bold → …` 顺序择优，
  分别取 Bold / Medium / Regular 三种字重，日志区用等宽字体（Cascadia Mono / Consolas）。
- 本机实测命中：**`bold=Noto Sans SC`、`medium=Noto Sans SC Medium`、`regular=Noto Sans SC`、`mono=Cascadia Mono`**
  （Noto Sans SC 是思源黑体的 Google 发行版，同一套字形）。
- **字体不打包进 exe**，避免 OFL 再分发问题；目标机没装时自动回退到微软雅黑 / Segoe UI，
  不会启动失败，且自检报告会打印实际选中的字体族。
- `tkinter` 默认字体（`TkDefaultFont` 等）也一并改到同一字族，避免弹窗、菜单出现字体不一致。

## 四点五、高 DPI 字体清晰度（字发虚的根因修复）

**问题现象**：界面字体边缘发虚、像被"糊"过一层。

**根因**（实测确认）：

```
注册表 AppliedDPI = 144        → 系统缩放 150%
未声明 DPI 感知时:
  Tk 报告 winfo_fpixels = 95.92 (误以为 96 DPI)
  屏幕报告 1707×1067 (虚拟化后的逻辑分辨率)
声明 DPI 感知后:
  屏幕报告 2560×1600 (真实物理分辨率)
```

进程没有声明 DPI 感知时，Windows 会把整个窗口按 150% **先放大再光栅化** ——
字体点阵被整体拉伸，笔画边缘自然发虚；同时 Tk 还以为自己是 96 DPI，字号与像素对不上，
造成"字小 + 糊"的双重问题。

**修复**（`bwm_theme.enable_dpi_awareness` + `compute_scale`）：

1. **在 import tkinter 之前**调用 `SetProcessDpiAwarenessContext(-4)`（Per-Monitor V2），
   失败则依次回退 `shcore.SetProcessDpiAwareness(2)`（Per-Monitor）、`SetProcessDPIAware()`（系统级）。
2. 读取真实 DPI（`GetDeviceCaps(LOGPIXELSX)`），得到缩放系数 `UI_SCALE = dpi/96`（本机 1.5）。
3. 字号按缩放系数放大并留有余量：`base = round(9 * (1 + (s-1)*0.75))`
   —— s=1.5 时正文 12pt / 卡片标题 13pt / 主标题 19pt，观感与 100% 缩放下一致，
   但**按真实物理像素渲染，笔画锐利**。
4. 窗口尺寸、最小尺寸、警戒线高度、进度条粗细、滚动条宽度、日志行高统一走 `sp()` 缩放；
   默认窗口取屏幕的 94%/92% 上限，避免小屏上超出可视区。
5. 支持环境变量 `BWM_UI_SCALE` 手动覆盖缩放系数（调试或特殊屏用）。

**实测对比**：

| | 修复前 | 修复后 |
|---|---|---|
| 屏幕报告 | 1707×1067（虚拟） | 2560×1600（物理） |
| winfo_fpixels | 95.92 | 按真实 DPI |
| 字体渲染 | 整体拉伸 1.5 倍后光栅化 → 发虚 | 直接按物理像素光栅化 → 锐利 |

自检报告新增该行，方便在别的机器上核对：
`ui_scale -> dpi=144 scale=1.50 dpi_aware=True ui_scale=1.50`

## 五、界面精简

- 去掉了 v0.2 卡片里多余的图标与说明文字，每页信息层级压缩为：**拖拽区 → 参数 → 主按钮**。
- 提取页把"密码 A / 密码 B"合并到同一行，历史密码做成一行小标签，纵向更紧凑。
- 主按钮只有一个（强调色实底），其余全部是弱化的描边按钮，视觉焦点唯一。
- 窗口默认逻辑 900×760（150% 缩放下为 1350×1140 物理像素），最小 720×580；
  内容顶部对齐，拉大窗口不会出现控件被纵向拉伸变形或中间大块空白。

## 六、本轮顺手修掉的两个缺陷

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | `App` 销毁后 `_drain_log` 的 `after` 定时器仍在排队 | 关窗时 Tk 报 `invalid command name ..._drain_log` | 保存定时器 id，重写 `destroy()` 先 `after_cancel`；回调里对 `TclError` 兜底 |
| 2 | `DropZone.set_file(None)` 会丢掉默认提示文案 | 清空后拖拽区只剩"尚未选择文件"，引导语消失 | 构造时记下 `self._default`，清空时还原 |

（另有几处自测中暴露的接线错误：`▾` 历史菜单 `_fill` 参数个数不匹配、`dnd_bind` 在回退分支下不存在等，均已修复。）
